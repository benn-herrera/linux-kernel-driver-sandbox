# ARCHITECTURE – api_gen

How this implementation meets SPEC.md. Standard-library Python, 3.11 or later for `tomllib`, run inside the build container, plus the container's `rustfmt`, which lays out the three Rust outputs: the emitters render each construct in one plain form and `rustfmt` decides the layout, so no Python code models rustfmt's rules; where it runs and what consumes its output is in the root ARCHITECTURE.md, "API generation".

## Shape

One pass, three stages, no state between runs:

```
definition ──load──▶ Api (frozen dataclasses) ──each selected emitter's validate──▶ selected emitters ──▶ files
```

- `model.py`: `load()` reads the TOML and `from_dict()` turns it into an `Api`. Every language-independent rule in SPEC.md "The definition" is enforced here: identifier syntax, no leading `_` on a name, uniqueness, ranges (every untyped constant, its literal terms and its sum fit its group's `_base_type`, every enum entry its enum's), distinct values within an enum, references (a sum's terms share its base type), lifecycle shape, `_class` lowercase (a class name collision under a binding's casing is that binding's objection), where `_optional` may appear (only on a parameter with a `_ref`, and on `memory` only with `_ref = "in"`), what a literal sum term may be (parsed once, by `_term()`), and which strings may be emitted inside a string literal (`check_literal_text()`, also applied to `--library` and `--project`), `_wrapped_api._header` being relative (neither absolute nor beginning with `../`; stored as written), a docstring's lack of a line break, and a plain group's sum's running total term by term (`_check_running_sum()`; a bit group's terms are disjoint, so each of its running totals fits as its terms do). Failures raise `DefinitionError` with a message that names the table and key, and only the loops catch: each top-level item, struct field and function parameter is parsed inside an `_Objections` collector, the cross-item checks run over what parsed, a type whose name another type or a builtin already holds is dropped as a struct that failed is, so the clash reports once, and one `DefinitionErrors` carries every objection in the items' document order (a lone one is raised as itself), except that an unknown top-level table, a missing or malformed `[_general]` or a file that is not TOML stops alone before collection starts. The granularity is uneven by design: a constant group or an enum stops at its first bad entry, while a struct's fields and a function's parameters each report every objection. A reference to an item that failed reports an unknown name, so a failed item's objection is followed by one per reference to it.
- `naming.py`: every SPEC.md "Naming" rule as a pure function of namespace and name, among them `lua_to_string()`, a conversion's Lua name, and `unknown_value_name()` and `NO_FLAGS`, the texts a conversion returns for a value with no entry and for a zero bit value; `BUILTIN_C_TYPES`, the one map from a builtin type to its C spelling that the model and every emitter read; and `BASE_C_TYPES`, the one map from a `_base_type` to its C type, `<stdint.h>` constant macro and value range, so a new base type is one row; the loader's range checks and the Lua emitter's signed-flag check read the range from it. Emitters never build a generated name by string concatenation of their own.
- `emitters/`: the output modules, as a package.
  - `emitters/__init__.py`: `EMITTERS`, the registry: one table in output order from output token to module (`h`, `hpp`, `lua`, `stub_cpp`, `rs`, `abi_rs`, `stub_rs`), built from static imports. It is the whole of what the generator knows about emitters.
  - `emitters/emitter.py`: `Emitter`, the protocol every output module meets and the generator calls through: `LABEL: str`, `validate(api) -> list[str]`, `output_path(*, name, project) -> Path`, the output's path relative to the generated directory, and `emit(api, *, source_name, name, library, project) -> str`, `name` being the definition's `_general._name`; and `ToolError`, which an `emit` raises when an external tool it runs is missing or fails.
  - `emitters/c.py`, the C language facts: `C_KEYWORDS`; type mapping, `c_type()` and `param_type()`; `int_literal()` and `typed_literal()`; `c_params()`, a parameter's C `(type, name)` pairs, a `memory` one its pointer and count (`rust.py` expands one for Rust the same way), and `param_list()`, the one place those pairs join into a signature's parameter list text, so every C and C++ signature matches the header's; `header_macros()`; `type_names()`, the fixed-width types and typedefs the declarations spell, and `parameter_type_objections()`, the refusal of a parameter named like one, which the header, the C++ stub and the wrapper share, since in a prototype the name hides the type from every parameter after it; and `declarations()`, so the header and the Lua module's FFI declarations are one rendering of the same structs and functions.
  - `emitters/cpp.py`, the C++ language facts: `CPP_KEYWORDS`, which takes the C keywords C++ shares from `c`, and `cpp_keyword_objections()`, the keyword check of both C++ translation units, the wrapper and the stub.
  - `emitters/rust.py`, the Rust language facts: `rustfmt()`, which every Rust `emit` returns its text through, run as `rustfmt --edition 2024 --config-path /dev/null` so no `rustfmt.toml` anywhere reaches it, raising `ToolError` when `rustfmt` is missing or fails; `RUST_KEYWORDS` (the strict, reserved and weak keywords of editions 2021 and 2024) and `rust_keyword_objections()`; `snake_case_objections()`, rustc's `non_snake_case` test (an uppercase letter or `__` once the ends are trimmed of `_`) over the (where, rendered name) pairs an emitter passes, each emitter passing only the names the lint reaches in its file, with `field_names()`, `param_names()` (a parameter and its `p_count`) and `enum_conversion_names()` the pairs the binding and the relay share; `opaque_field_objections()`; the FFI type mapping, `rust_type()`, and `signature()`, a function's FFI signature on one line, each taking a `path` (`ffi::`) for a file whose C names live in a module of their own; `value_type()`, a non-memory type as a file with the re-exports in scope spells it, a boxed scalar or struct by its re-export and anything else as `rust_type()` under `ffi::`, on which `implementation_type()`, the one spelling of a parameter as the relay hands it to the implementation, which the relay's pin and the stub's signatures share, and the binding's own spelling build; `out_default()`, the function an `out` local starts from, a null handle or `value_type()`'s `default`, which the binding and the relay share; the docstring lines `doc_comment()` (`///`) and `function_docs()`, the one rendering of a function's `///` lines (its docstring, a bare `///` where more follows, each parameter's from `Function.docs()`, any extra lines, a `# Safety` section) that the relay's exports, the stub, the binding's `ffi` block and its class methods share; `many_arguments_allow()`, clippy's `too_many_arguments` threshold, which the stub and the binding's methods share; `version_constant()`, `constant_group()` and `string_group()`, each C-named or, for the binding, unprefixed, `enum_alias()`, and `type_definitions()`, the `#[repr(C)]` blocks. What the binding and the relay both carry is rendered here once, so the two agree byte for byte: `ffi_module()`, the `pub mod ffi` wrapper indenting the blocks it is given (the relay's C-named constants and `type_definitions()`, the binding's `enum_alias()` and `type_definitions()` with its `extern` block after them), `enum_block()`, an enum with its `TryFrom`, conversion and `Display`, and `reexports()`; and with them the checks both make, `camel_keyword_objections()` over `camel_names()` (`type_names()`, the enums, boxed scalars and structs, and the enum entries), `prelude_names()`, the prelude's names a file passes as module-scope definers (by default `PRELUDE_NAMES`, the stub's list, a hand-written crate root's common names; the binding and the relay each pass the ones their own text spells, since a prelude trait whose name an item takes stays in scope for method calls), `module_names()` (the enums and re-exports a module scope defines) and `enum_member_objections()`. Every helper pairing a name with where it is returns `(where, name)`, the order `model.duplicates()` takes. `abi_file_name()` is the relay's file name, which the relay's `output_path` and the stub's `include!` share. A literal is spelled by `c.int_literal()`, whose sign-in-front form Rust shares.
  - `emit_c.py`, `emit_binding_cpp.py`, `emit_binding_lua.py`, `emit_binding_rs.py`, `emit_abi_rs.py`, `emit_stub_cpp.py`, `emit_stub_rs.py`, each named for what it emits and then its flavour: one `Emitter` per output, each stating its own path beside its `emit`. `validate` returns every objection that output has, each prefixed with its `LABEL` (`header:`, `wrapper:`, `lua:`, `stub:`, `rust:`, `rust_abi:`, `rust_stub:`); `emit` returns the file's text, every emitter taking the same keywords and ignoring those it does not use. An `emit` assumes its `validate` returned nothing and does not check again. An emitter is the protocol's four names and nothing else public: what emitters share is a language fact, in that language's module, and what one emitter alone uses, its own keyword table included, is private to it. Emitters share the model, `naming` and the language modules, and never import one another.
- `__main__.py`: the command line, emitter-blind: it imports no emitter, only `EMITTERS`. Parses arguments, loads, runs each selected emitter's `validate` and reports every objection at once, one line each; a message several emitters raise identically prints once, its line naming every one of them, comma-joined in `EMITTERS` order (`header, wrapper, stub: ...`). It then runs the selected emitters in memory and writes, so a failing definition leaves no partial output; a `ToolError` from an `emit` is reported as `api_gen: <message>`, exit 2, before anything is written. The registry's keys are the vocabulary `--outputs` accepts (`TOKENS`); generation calls each selected module's `LABEL`, `validate`, `output_path` and `emit` and nothing else, and `gendeps` calls `output_path` too, so each output's path is stated once, by its emitter. `--project` and `--library` are checked in one place, `_flag_objections()` (not empty, and `model.check_literal_text()`), their objections printed after the definition's in the same run; `--library` overrides `_general._library`; `_linkage_objections()` raises the missing-library objection, which needs the flag as well as the definition and so cannot come from `validate(api)`, under the labels of the registry's `lua` and `rs` entries that are selected, and beside it, with `rs` selected, the refusal of a library `naming.rust_link_name()` cannot link, since it too needs the flag, both skipped where the flag itself was refused; `naming` states the `lib<name>.so` rule once, for this check and the binding's `#[link]`. Every objection, the loader's, the emitters' and the flag's, prints through one helper, `_report()`, which `gendeps` shares. It always writes what is selected; whether it runs at all is make's decision, from the definition's mtime. Its `gendeps` mode loads the definition for its `_general._name` and prints the make rules `exercises/gen.mk` includes, from the same `output_path` calls, so the naming rule has a single home and the build file carries none of it. `exercises/gen.mk` passes its `OUTPUTS` variable, `h,hpp,lua,stub_cpp` (`rs`, `abi_rs` and `stub_rs` are opt-in) unless the exercise's `api_def/Makefile` sets it before the include or the make command line sets it (an environment variable of that name is ignored), to `gendeps` as `--outputs`, and the fragment's rule carries the same selection into generation. `adef.mk` is remade only when the definition changes, and a dropped output's file stays under the generated directory, so a changed `OUTPUTS` needs `userspace-clean-vdev`; `gen.mk` says so beside the variable.

## The model

`Api` is a frozen dataclass tree whose every item is a `Node`, a keyword-only base carrying `name` and `docstring`: `Group` of `BitConst`, of plain constants as `EnumEntry`, or of `StringConst`; `TypedConst` of `EnumEntry`; `OpaqueRef`; `BoxedScalar`, carrying its `base_type`, one of `INTEGER_TYPES`; `Struct` of `Field`; `Function` of `Param`. `Api` itself and its optional `WrappedApi` are not nodes. Tuples throughout, in document order. Each of the three untyped-constant kinds (bit, plain, string) is an array of `Group`s, each carrying a docstring and a base type (`None` for a string group), for the emitters that render one block per group; a group has no name in the definition, so its `name` is where it is, `untyped_const[0]`; `Api.bit_consts`, `Api.consts` and `Api.string_consts` are every entry across a kind's groups in order, for everything that treats constants one by one: literal values, composition, uniqueness, pins. A composed entry (a list of terms, each an earlier same-table entry or a literal integer) carries both its resolved `value` and its `parts` in the order written, each the entry's name or a `LiteralTerm` holding the literal's value and the base it was written in, since the header renders a sum symbolically from `parts` while every other emitter uses `value` directly; no emitter parses a term again; the loader refuses a bit-group sum whose terms share a bit, and any sum with a term of another base type. `Api.constant_names()` lists every constant with where it is written, enum entries included unless asked not to and the version constant where asked: the one walk of the constants, read by `names()`, the loader's uniqueness check, the header's macro check and the bindings' namespace and module checks. `Api.classes()` is the class shape every binding builds, one `ClassShape` per opaque ref with a `_ctor`: the ctor, its handle parameter, the other `out`s it caches, the methods and the dtor. A method is any other function whose first parameter is the opaque by value, the one membership decided by a parameter's shape, since SPEC.md states it that way. `ClassShape.class_params()` is the parameters a class renders, each of the ctor's and each method's but its first, the one scope of every binding's refusal of a parameter named like a name its class code uses, since a parameter no class renders reaches a binding only through its raw declaration; `ClassShape.members()` is the class's member list, the binding's own fixed members, then the methods and the cached `out`s, for each binding's class duplicate check. `Api.success_entry()` is a function's zero-valued result entry. `duplicates()` is the one duplicate-name finder over `(where, name)` pairs: the loader's C-identifier uniqueness check and each binding's namespace, enum-class, module-field and class-member checks build their objections from it, every binding through `duplicate_objections()`, the one wording of a name defined twice; `generated_name_objections()` is the one wording of a definition name the generated code itself uses where it would be in scope. A bit or plain `Group` and a `TypedConst` carry `to_string`, the `_to_string` name or `None`; a string group's is always `None`, since the loader refuses the property there as an unknown key. `single_bit_entries()` is the one statement of which bit entries a conversion decomposes a value into, read by every emitter that renders one, and `named_values()` its counterpart for a plain group, one entry per value, the later where two share one, read by the C++, Lua and Rust conversions. `Api.kind()` answers the one question every emitter asks, which category a type name belongs to (`builtin`, `enum`, `opaque`, `boxed` or `struct`), from the validated tree rather than by re-checking; a boxed scalar needs no rule of its own in the loader beyond its table, since `_return` already admits only a `typed_const` and `_count` only a `memory` parameter. `Api.names()` lists every name the definition gives with where it is written, `_to_string` names included (`typed_const.result._to_string`, `untyped_bit_const[0]._to_string`), so each emitter's `validate` checks its own keywords over one walk of the tree.

Normalisation happens on the way in. A described item's `_` properties are split from its members first, so no member check ever sees a property. `_attributes()` turns a naked value into the table it is sugar for, so a bare type string and a `{ _type, ... }` table become the same `Param` or `Field`, and a bare integer and a `{ _value, _format, _docstring }` table the same `EnumEntry`; `tomllib` already makes a nested `[a.b.c]` table and an inline one the same dict. `Param.ref` is `None` or one of `in`, `out`, `inout`; `Param.count_type` is set for `memory` only. Emitters see one shape.

Order is document order because `tomllib` builds insertion-ordered dicts, a guarantee Python makes since 3.7 that the TOML specification does not. The loader's docstring states the reliance; it is the one place the project depends on it.

## Emitters

- **Header** (`emit_c.emit()`): `validate()` refuses a C keyword as any name, a parameter named like a type the declarations spell (`c.parameter_type_objections()`), a typed enum entry above the `i32` maximum (a C17 enumerator is an `int`, whatever the enum's base type), and a constant whose C name is one of `c.header_macros()`, the set of macros the header defines or tests for itself. Renders the blocks in SPEC.md order. `c.declarations()` renders opaque refs, then boxed scalars, then structs, so a struct may hold a boxed scalar, then functions, and takes the function prefix as an argument, so the header passes `NS_API ` and the Lua module's cdef passes nothing, and `constants=False` for the cdef. In `c`, `_constant_group()` renders a bit or plain group as its run of macros, and `_sum()` a composed entry from `parts`; `typed_literal()` is the one spelling of a value as a constant of its base type, the sign outside the macro, used for a group's values, its literal terms and a negative enum entry. The C++ wrapper's constants are `auto` from these macros, so the header is the one place a constant's type is spelled. Type mapping is `c.c_type()` and `c.param_type()`. The wrapped API and its pins are one trailing `#if defined(NS_IMPL)` block from `WrappedApi`, includes (the wrapped API's header as `emit()`'s `project` joined to `WrappedApi.header`) and `static_assert` lines, after every constant they name; `emit()` renders it and `c.declarations()` does not.
- **Lua module** (`emit_binding_lua.emit()`): `_cdef()` is the `ffi.cdef` block, a typedef of its base type per enum and then `c.declarations()` without constants or a function prefix. `_constant_sections()` renders every constant from the model's already-resolved `value` — a composed entry's sum, overlap-checked for a bit group, is computed once in `model.py`, not recomputed here — so the numbers come from the model and not from the FFI. `_class()` builds one class per `Api.classes()` shape; nothing about the class is inferred from names. `_marshal()` turns a parameter list into four lists at once: the Lua arguments, the C call arguments, the cdata allocations for non-memory reference parameters (copied in from the argument for `in` and `inout`, zeroed for `out`), and the values returned for `out` and `inout`; a `memory` parameter is a Lua string — `in` passed straight through with its length as the count, `out` and `inout` each allocated into a buffer that is returned as a string via `ffi.string`. A boxed scalar is boxed there and nowhere else: by value, an allocation builds its FFI struct from the caller's number; by reference, `_box()` allocates the struct itself rather than a one-element array, and `_read_back()` returns its `.value` as the base type is returned. `_unboxed()` names the base type the caller passes, which `_type_check()` asserts. `_lua_value()` meets a boxed scalar only as a struct field and copies it, since indexing a struct-typed field yields a reference the GC does not keep its parent alive for. The constructor uses the same arguments, call and allocations. `_lookup()` renders an enum's or plain group's conversion as a table keyed by value, a plain group's entries from `named_values()` so no key repeats (the loader refuses a shared value in an enum), and `_bit_to_string()` a bit group's with the `bit` library, bound as a module local only when a bit group has a conversion. `validate()` refuses a Lua keyword as any name, a bit flag above the `i32` maximum (LuaJIT's `bit` operations are signed 32-bit), a parameter of `ClassShape.class_params()` named like one of `_GENERATED_NAMES` (every free name the generated text binds or references where a class function's arguments are in scope, a module-level tuple beside the templates), and through `duplicate_objections()` a class member defined twice (`new`, `_handle`, a method, the dtor's method or a cached `out`) and a module field defined twice (a constant, a conversion under its rendered name from `_conversion_names()`, `raw`, or a class), each naming every definer. LuaJIT's cdef parser does not scope a prototype's parameter names, so the module needs no refusal of a parameter named like a C type.
- **C++ wrapper** (`emit_binding_cpp.emit()`): an enum's conversion is rendered after its `enum class` by `_enum()`, a plain group's after its constants by `_plain_to_string()`, both through `_switch()`, which renders one case per entry it is given, a plain group's from `named_values()`, since duplicate case labels do not compile, and a bit group's after its constants by `_bit_to_string()`; `<string>` and `<charconv>` are included only when a group's conversion needs them. Boxed scalars and structs are one run of aliases, boxed scalars first, and `_ref_type()` spells either by its alias; a boxed scalar has no other code in the wrapper. `validate()` refuses a C++ keyword as any name, through `cpp.cpp_keyword_objections()` over `cpp.CPP_KEYWORDS`, which holds the C keywords C++ shares since the wrapper includes the header; the header's `c.parameter_type_objections()`, since the wrapper compiles the header's declarations; a parameter of `ClassShape.class_params()` named like one of its own `_GENERATED_NAMES` (the fixed names the class's generated text binds where a parameter is in scope, a module-level tuple beside the templates) or of `_rendered_names()` (the names it spells from the definition there: the C functions and typedefs, the fixed-width types, and the namespace's enum classes, boxed scalar and struct aliases and classes); a method named like one of the latter; and a name defined twice in the namespace, an enum class or a class (`ClassShape.members()`), naming every definer; `release` is the class's own member only when a `_dtor` generates it. The namespace list holds each group's conversion name and each distinct enum conversion name once, so enums sharing a name overload rather than collide, while an enum's conversion named like a group's is still a duplicate.
- **Stub** (`emit_stub_cpp.emit()`): `validate()` refuses a C++ keyword, from `cpp.cpp_keyword_objections()`, the check it shares with the wrapper, and a parameter named like a C type, from `c.parameter_type_objections()`, the check it shares with the header whose signatures it repeats. Every body is `return {};`, which C++ value-initialises to the return enum's zero entry; the stub has no need of a failure result to pick.
- **Rust binding** (`emit_binding_rs.emit()`): the `ffi` module is `rust.ffi_module()` over `rust.enum_alias()` and `rust.type_definitions()`, then the `unsafe extern "C"` block of `rust.signature()` declarations under `rust.function_docs()`; the module scope is `rust`'s constant blocks unprefixed, each group's conversion after its constants (`_plain_to_string()` over `named_values()`, and `_bit_to_string()` over `single_bit_entries()`), `rust.enum_block()` per enum, `rust.reexports()` and one `_class()` per `Api.classes()` shape; `emit()` returns the whole through `rust.rustfmt()`. `_safe_type()` spells a type at module scope, an enum by its UpperCamel name and anything else by `rust.value_type()`. `_marshal()` turns a parameter list into the signature's parameters, the locals before the call (a received `out` starting from `rust.out_default()`), the call's arguments, the conversions after a successful result, the `out`s the call writes and the raw handles the caller vouches for: an opaque by value or `in` is its class by reference where it has a class, passing `.handle` or its address, and otherwise, or where the library may replace it (`out`, `inout`), the raw `ffi` handle; a raw handle the library reads (by value, `in` or `inout`) is recorded in `unchecked`, which `_method()` turns into a `pub unsafe fn` with one `# Safety` line per such parameter; `_method()` also adds `rust.many_arguments_allow()`, the receiver counted. `_received_out()` states which `out`s become a local the caller receives (an enum one among them, converted after the call in `_marshal()`), and `_through_raw_local()` which enum parameters travel through a `<p>_raw` local of the base type, which `_marshal_enum_ref()` renders. `_checked_call()` is the body of `create`, every method and `release`, its call under one of two fixed `// SAFETY:` texts, `_SAFETY_CREATE` for `create` and `_SAFETY`, which adds the handle clause, for the rest and for `drop`. `validate()` refuses a Rust keyword, and a name whose UpperCamel rendering is one; through `rust.snake_case_objections()`, the names rustc's lint reaches in this file: fields, conversion and method names, and each parameter of `ClassShape.class_params()` with its `p_count` and `p_raw` locals, never an `ffi` function's name or parameters; an opaque field through `rust.opaque_field_objections()`; a parameter of `ClassShape.class_params()` named like one of `_GENERATED_NAMES` (`raw` and `result`, the locals every call binds) or a `<p>_raw` local of its function; and a name defined twice at module scope (where `_PRELUDE_NAMES`, the prelude names this file spells unqualified, count as definers), in an enum (`rust.enum_member_objections()`) or in a class (`ClassShape.members()`), through `duplicate_objections()`. Every other name the class code reaches is a path's first segment, a type or a field (`ffi::xy_f`, `u32::try_from`, `self.handle`), which no parameter or method can shadow; a ctor handle `out` named `handle` initialises the field by shorthand.
- **Rust relay** (`emit_abi_rs.emit()`): `rust.ffi_module()` over `_constants()`, the C-named `pub const` and enum alias blocks, and `rust.type_definitions()`; `rust.enum_block()` per enum and `rust.reexports()`, the binding's own text; where some parameter is `memory`, `c_len` (`_LEN_TEXT`) and then the buffer helpers `c_bytes`, `c_bytes_mut` and `c_bytes_zeroed`, fixed text in `_HELPER_TEXT`, each emitted only when a `memory` parameter of its direction exists, and called as `self::c_bytes(...)`, a path no parameter shadows; one `_relay()` per function; and last the wrapped API from `WrappedApi`: `mod wrapped_api` including `$OUT_DIR/wrapped_api.rs`, then one `assert!` per pin against `ffi::NS_KEY`, all through `rust.rustfmt()`. `_relay()` is an export through `rust.signature()` with the `ffi::` path under `#[unsafe(no_mangle)]`, under `rust.function_docs()` with a `may be null` line per `_optional` parameter and the fixed `# Safety` text; its body is a `naming.rust_local()` local per pointer parameter (a buffer helper's slice for `memory`, a copy `read()` from the pointer for `in` and `inout`, and for `out`, where the pointer is not null, `rust.out_default()`: a null handle or the type's `default`), the pin, `const IMPLEMENTATION: fn(...)` spelled by `rust.implementation_type()` and bound to `crate::f`, an upper-case item no parameter can take since each passes `non_snake_case`, under an `allow` of clippy's `type_complexity` on every pin, since that lint's score cannot be predicted from the definition, then the call through it, a write-back per non-memory `out` and `inout`, and a `match` turning `Ok(())` into the zero entry from `Api.success_entry()` and `Err(e)` into `e as` the C enum. Every raw pointer operation is in an `unsafe { }` block of its own, as edition 2024 requires inside an `unsafe fn`, and the body holds no `expect` or `unwrap`. `validate()` refuses what `rust` refuses for the binding's shared blocks (a keyword, an UpperCamel keyword rendering, an opaque field, a duplicate in an enum), the `non_snake_case` names this file renders (fields, enum conversions, parameters, their `p_count` and `p_local`; an export's name is exempt), a non-memory `out` or `inout` parameter named like one of `_GENERATED_NAMES` (`result`, the local the write-backs follow, which then reach each such parameter by name), any parameter named like another parameter's local, and a name defined twice at module scope, `c_len` and the helpers among them, where `_PRELUDE_NAMES`, the prelude names this file spells unqualified, count as definers. The pins read the `bindgen` rendering of the wrapped API's header that the implementation's build writes into `OUT_DIR`, a cargo crate's `build.rs` being the idiom; the generator never parses that header, as it never does for the C pins.
- **Rust stub** (`emit_stub_rs.emit()`): `validate()` refuses a Rust keyword; through `rust.snake_case_objections()`, a function or parameter name, the implementation functions being plain `fn`s the lint reaches; and over `_imported()`, the types the `use` line names, an UpperCamel keyword rendering (`rust.camel_keyword_objections()`) and a duplicate of `rust.prelude_names()`. It renders `pub mod abi` including `rust.abi_file_name()` from `$API_GEN_RUST_DIR`, the `use abi::{...}` line from `_imports()` in no order, since rustfmt sorts it and makes a one-name list a plain `use`, and one `_definition()` per function: `rust.implementation_type()` spells each parameter as the relay hands it over, the doc comment is `rust.function_docs()`, `rust.many_arguments_allow()` precedes the signature, and the body is a `let _` per parameter and `Ok(())`, all through `rust.rustfmt()`.

## What the emitters cannot express

- `_optional` is documentation only in the C header, which has no expression for it, and in the Rust relay, which hands every pointer over as an `Option` whether or not it is `_optional`; the C++ wrapper, the Lua module and the Rust binding render it, as an optional pointer parameter, a nil-admitting argument and an `Option` respectively.
- The spelling of numbers as written. `tomllib` yields integers, so the definition says `_format = "hex"` where it wants hex; without it a value is decimal whatever the file said.

## Extension points

- A new output: copy `Emitter`'s four signatures into a new `emitters/emit_<what>_<flavor>.py`, its `output_path` naming a path under the output directory that mirrors where it will be staged, or, for a file nothing stages, under the subtree of its kind (`stub/`, `rust/`), and add one line to `EMITTERS`, its token to the module. `emit_stub_cpp.py`, `emit_abi_rs.py` and `emit_binding_cpp.py` are the worked examples.
- A per-API hooks module beside the definition is reserved for peculiarities. Its interface is deliberately undefined until the first real case shows what it needs; the model is plain data so a hook can adjust it without the generator knowing why.
