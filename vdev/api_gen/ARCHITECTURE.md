# ARCHITECTURE – api_gen

How this implementation meets SPEC.md. Standard-library Python, 3.11 or later for `tomllib`, run inside the build container; where it runs and what consumes its output is in the root ARCHITECTURE.md, "API generation".

## Shape

One pass, three stages, no state between runs:

```
definition ──load──▶ Api (frozen dataclasses) ──each selected emitter's validate──▶ selected emitters ──▶ files
```

- `model.py`: `load()` reads the TOML and `from_dict()` turns it into an `Api`. Every language-independent rule in SPEC.md "The definition" is enforced here: identifier syntax, no leading `_` on a name, uniqueness, ranges (every untyped constant, its literal terms and its sum fit its group's `_base_type`, every enum entry its enum's), references (a sum's terms share its base type), lifecycle shape, `_class` lowercase (a class name collision under a binding's casing is that binding's objection), where `_optional` may appear (only on a parameter with a `_ref`, and on `memory` only with `_ref = "in"`), what a literal sum term may be (parsed once, by `_term()`), and which strings may be emitted inside a string literal (`check_literal_text()`, also applied to `--library`). Failures raise `DefinitionError` with a message that names the table and key; the loader stops at the first.
- `naming.py`: every SPEC.md "Naming" rule as a pure function of namespace and name, among them `lua_to_string()`, a conversion's Lua name, and `unknown_value_name()` and `NO_FLAGS`, the texts a conversion returns for a value with no entry and for a zero bit value; `BUILTIN_C_TYPES`, the one map from a builtin type to its C spelling that the model and every emitter read; and `BASE_C_TYPES`, the one map from a `_base_type` to its C type, `<stdint.h>` constant macro and value range, so a new base type is one row; the loader's range checks and the Lua emitter's signed-flag check read the range from it. Emitters never build a generated name by string concatenation of their own.
- `emitters/`: the output modules, as a package.
  - `emitters/__init__.py`: `EMITTERS`, the registry: one table in output order from output token to module (`h`, `hpp`, `lua`, `stub_cpp`), built from static imports. It is the whole of what the generator knows about emitters.
  - `emitters/emitter.py`: `Emitter`, the protocol every output module meets and the generator calls through: `LABEL: str`, `validate(api) -> list[str]`, `output_path(*, stem, exercise) -> Path`, the output's path relative to the generated directory, and `emit(api, *, source_name, stem, library) -> str`.
  - `emitters/c.py`, the C language facts: `C_KEYWORDS`; type mapping, `c_type()` and `param_type()`; `int_literal()` and `typed_literal()`; `c_params()`, the one place a `memory` parameter becomes its pointer and count pair, and `param_list()`, the one place those `(type, name)` pairs join into a signature's parameter list text, so every emitter's signatures match the header's; `header_macros()`; and `declarations()` with `cdef()`, so the header and the Lua module's FFI declarations are one rendering of the same structs and functions.
  - `emitters/cpp.py`, the C++ language facts: `CPP_KEYWORDS`, which takes the C keywords C++ shares from `c`, and `cpp_keyword_objections()`, the keyword check of both C++ translation units, the wrapper and the stub.
  - `emit_c.py`, `emit_binding_cpp.py`, `emit_binding_lua.py`, `emit_stub_cpp.py`, each named for what it emits and then its flavour: one `Emitter` per output, each stating its own path beside its `emit`. `validate` returns every objection that output has, each prefixed with its `LABEL` (`header:`, `wrapper:`, `lua:`, `stub:`); `emit` returns the file's text, every emitter taking the same keywords and ignoring those it does not use. An `emit` assumes its `validate` returned nothing and does not check again. An emitter is the protocol's four names and nothing else public: what emitters share is a language fact, in that language's module, and what one emitter alone uses, its own keyword table included, is private to it. Emitters share the model, `naming` and the language modules, and never import one another.
- `__main__.py`: the command line, emitter-blind: it imports no emitter, only `EMITTERS`. Parses arguments, loads, runs each selected emitter's `validate` and reports every objection at once, one line each; a message several emitters raise identically prints once, its line naming every one of them, comma-joined in `EMITTERS` order (`header, wrapper, stub: ...`). It then runs the selected emitters in memory and writes, so a failing definition leaves no partial output. The registry's keys are the vocabulary `--outputs` accepts (`TOKENS`); generation calls each selected module's `LABEL`, `validate`, `output_path` and `emit` and nothing else, and `gendeps` calls `output_path` too, so each output's path is stated once, by its emitter. An empty `--library` is a usage error; the missing-library objection, which needs the flag as well as the definition and so cannot come from `validate(api)`, is raised here under the label of the registry's `lua` entry. It always writes what is selected; whether it runs at all is make's decision, from the definition's mtime. Its `gendeps` mode prints the make rules `exercises/gen.mk` includes, from the same `output_path` calls, so the naming rule has a single home and the build file carries none of it. `exercises/gen.mk` passes its `OUTPUTS` variable, all four tokens unless the exercise's `api_def/Makefile` sets it before the include or the make command line sets it (an environment variable of that name is ignored), to `gendeps` as `--outputs`, and the fragment's rule carries the same selection into generation. `adef.mk` is remade only when the definition changes, and a dropped output's file stays under the generated directory, so a changed `OUTPUTS` needs `userspace-clean-vdev`; `gen.mk` says so beside the variable.

## The model

`Api` is a frozen dataclass tree whose every item is a `Node`, a keyword-only base carrying `name` and `docstring`: `Group` of `BitConst`, of plain constants as `EnumEntry`, or of `StringConst`; `TypedConst` of `EnumEntry`; `OpaqueRef`; `BoxedScalar`, carrying its `base_type`, one of `INTEGER_TYPES`; `Struct` of `Field`; `Function` of `Param`. `Api` itself and its optional `DriverData` are not nodes. Tuples throughout, in document order. Each of the three untyped-constant kinds (bit, plain, string) is an array of `Group`s, each carrying a docstring and a base type (`None` for a string group), for the emitters that render one block per group; a group has no name in the definition, so its `name` is where it is, `untyped_const[0]`; `Api.bit_consts`, `Api.consts` and `Api.string_consts` are every entry across a kind's groups in order, for everything that treats constants one by one: literal values, composition, uniqueness, pins. A composed entry (a list of terms, each an earlier same-table entry or a literal integer) carries both its resolved `value` and its `parts` in the order written, each the entry's name or a `LiteralTerm` holding the literal's value and the base it was written in, since the header renders a sum symbolically from `parts` while every other emitter uses `value` directly; no emitter parses a term again; the loader refuses a bit-group sum whose terms share a bit, and any sum with a term of another base type. `Api.constant_names()` lists every constant with where it is written, enum entries included unless asked not to: the one walk of the constants, read by `names()`, the loader's uniqueness check, the header's macro check and the wrapper's namespace check. `Api.classes()` is the class shape both bindings build, one `ClassShape` per opaque ref with a `_ctor`: the ctor, its handle parameter, the other `out`s it caches, the methods and the dtor. A method is any other function whose first parameter is the opaque by value, the one membership decided by a parameter's shape, since SPEC.md states it that way. `Api.success_entry()` is a function's zero-valued result entry. `duplicates()` is the one duplicate-name finder: the loader's C-identifier uniqueness check and each binding's namespace, enum-class, module-field and class-member checks build their objections from it. A bit or plain `Group` and a `TypedConst` carry `to_string`, the `_to_string` name or `None`; a string group's is always `None`, since the loader refuses the property there as an unknown key. `single_bit_entries()` is the one statement of which bit entries a conversion decomposes a value into, read by both emitters that render one. `Api.kind()` answers the one question every emitter asks, which category a type name belongs to (`builtin`, `enum`, `opaque`, `boxed` or `struct`), from the validated tree rather than by re-checking; a boxed scalar needs no rule of its own in the loader beyond its table, since `_return` already admits only a `typed_const` and `_count` only a `memory` parameter. `Api.names()` lists every name the definition gives with where it is written, `_to_string` names included (`typed_const.result._to_string`, `untyped_bit_const[0]._to_string`), so each emitter's `validate` checks its own keywords over one walk of the tree.

Normalisation happens on the way in. A described item's `_` properties are split from its members first, so no member check ever sees a property. `_attributes()` turns a naked value into the table it is sugar for, so a bare type string and a `{ _type, ... }` table become the same `Param` or `Field`, and a bare integer and a `{ _value, _format, _docstring }` table the same `EnumEntry`; `tomllib` already makes a nested `[a.b.c]` table and an inline one the same dict. `Param.ref` is `None` or one of `in`, `out`, `inout`; `Param.count_type` is set for `memory` only. Emitters see one shape.

Order is document order because `tomllib` builds insertion-ordered dicts, a guarantee Python makes since 3.7 that the TOML specification does not. The loader's docstring states the reliance; it is the one place the project depends on it.

## Emitters

- **Header** (`emit_c.emit()`): `validate()` refuses a C keyword as any name, a typed enum entry above the `i32` maximum (a C17 enumerator is an `int`, whatever the enum's base type), and a constant whose C name is one of `c.header_macros()`, the set of macros the header defines or tests for itself. Renders the blocks in SPEC.md order. `c.declarations()` renders opaque refs, then boxed scalars, then structs, so a struct may hold a boxed scalar, then functions, and takes the function prefix as an argument, so the header passes `NS_API ` and the cdef passes nothing, and `constants=False` for the cdef. In `c`, `_constant_group()` renders a bit or plain group as its run of macros, and `_sum()` a composed entry from `parts`; `typed_literal()` is the one spelling of a value as a constant of its base type, the sign outside the macro, used for a group's values, its literal terms and a negative enum entry. The C++ wrapper's constants are `auto` from these macros, so the header is the one place a constant's type is spelled. Type mapping is `c.c_type()` and `c.param_type()`. The ABI pins are one trailing `#if defined(NS_IMPL)` block from `DriverData`, includes and `static_assert` lines, after every constant they name; `emit()` renders it and `c.cdef()` does not.
- **Lua module** (`emit_binding_lua.emit()`): `_constant_sections()` renders every constant from the model's already-resolved `value` — a composed entry's sum, overlap-checked for a bit group, is computed once in `model.py`, not recomputed here — so the numbers come from the model and not from the FFI. `_class()` builds one class per `Api.classes()` shape; nothing about the class is inferred from names. `_marshal()` turns a parameter list into four lists at once: the Lua arguments, the C call arguments, the cdata allocations for non-memory reference parameters (copied in from the argument for `in` and `inout`, zeroed for `out`), and the values returned for `out` and `inout`; a `memory` parameter is a Lua string — `in` passed straight through with its length as the count, `out` and `inout` each allocated into a buffer that is returned as a string via `ffi.string`. A boxed scalar is boxed there and nowhere else: by value, an allocation builds its FFI struct from the caller's number; by reference, `_box()` allocates the struct itself rather than a one-element array, and `_read_back()` returns its `.value` as the base type is returned. `_unboxed()` names the base type the caller passes, which `_type_check()` asserts. `_lua_value()` meets a boxed scalar only as a struct field and copies it, since indexing a struct-typed field yields a reference the GC does not keep its parent alive for. The constructor uses the same arguments, call and allocations. `_lookup()` renders an enum's or plain group's conversion as a table keyed by value, deduplicated in Python so the last entry wins, and `_bit_to_string()` a bit group's with the `bit` library, bound as a module local only when a bit group has a conversion. `validate()` refuses a Lua keyword as any name, a bit flag above the `i32` maximum (LuaJIT's `bit` operations are signed 32-bit), a parameter named like one of `_GENERATED_NAMES` (every free name the generated text binds or references where a class function's arguments are in scope, a module-level tuple beside the templates), a member that would collide with `new`, `_handle`, a method or a cached `out`, and a module field defined twice — a constant, a conversion under its rendered name from `_conversion_names()`, `raw`, or a class — each naming every definer.
- **C++ wrapper** (`emit_binding_cpp.emit()`): an enum's conversion is rendered after its `enum class` by `_enum()`, a plain group's after its constants by `_plain_to_string()`, both through `_switch()`, and a bit group's after its constants by `_bit_to_string()`; `<string>` and `<charconv>` are included only when a group's conversion needs them. Boxed scalars and structs are one run of aliases, boxed scalars first, and `_ref_type()` spells either by its alias; a boxed scalar has no other code in the wrapper. `validate()` refuses a C++ keyword as any name, through `cpp.cpp_keyword_objections()` over `cpp.CPP_KEYWORDS`, which holds the C keywords C++ shares since the wrapper includes the header, a parameter named like one of its own `_GENERATED_NAMES` (the fixed names the class's generated text binds where a parameter is in scope, a module-level tuple beside the templates) or of `_rendered_names()` (the names it spells from the definition there: the C functions and typedefs, the fixed-width types, and the namespace's enum classes, boxed scalar and struct aliases and classes), a method named like one of the latter, and a name defined twice in the namespace, an enum class or a class, naming every definer; `release` is the class's own member only when a `_dtor` generates it. The namespace list holds each group's conversion name and each distinct enum conversion name once, so enums sharing a name overload rather than collide, while an enum's conversion named like a group's is still a duplicate.
- **Stub** (`emit_stub_cpp.emit()`): `validate()` refuses only a C++ keyword, from `cpp.cpp_keyword_objections()`, the check it shares with the wrapper. Every body is `return {};`, which C++ value-initialises to the return enum's zero entry; the stub has no need of a failure result to pick.

## What the emitters cannot express

- `_optional` is documentation only in the C header, which has no expression for it; the C++ wrapper and the Lua module both render it, as an optional pointer parameter and as a nil-admitting argument respectively.
- The spelling of numbers as written. `tomllib` yields integers, so the definition says `_format = "hex"` where it wants hex; without it a value is decimal whatever the file said.

## Tests

`tests/test_model.py`, `tests/test_header.py`, `tests/test_binding_lua.py`, `tests/test_binding_cpp.py`, `tests/test_stub_cpp.py` and `tests/test_cli.py` cover the generator's outputs by name — the loader's rules, the C header, the Lua module, the C++ wrapper, the C++ stub, each emitter's `validate` in its own file, and generation plus `gendeps`, with every `EMITTERS` module checked against each of `Emitter`'s signatures and for defining no other public name, and every token's path against SPEC.md's layout — standard `unittest` over a small fixture definition in a namespace of its own, so a test failure is about the generator and not about `tiny_compute`; each SPEC.md contract line has a test, and a line without one is a gap to close; `just api-gen-test-vdev` runs them in the container, the only place they run; `tests/test_compiled.py` compiles the header as C and C++, builds and runs the fixture's fake library under the C++ consumer and the Lua module under `luajit`, drives the `gendeps` fragment and `exercises/gen.mk`'s `OUTPUTS` through `make -n`, and round-trips every exercise's definition, against the container's pinned clang and luajit; `tests/support.py` is the home of `FIXTURE`, `KITCHEN_SINK`, `MINIMAL` and the helpers.

The end-to-end check is the project's own loop: `just test` generates from the real definition, builds the library against the generated header with the pins active, builds the test program, and runs the Lua test through the generated module in the guest.

## Extension points

- A new output: copy `Emitter`'s four signatures into a new `emitters/emit_<what>_<flavor>.py`, its `output_path` naming a path under the output directory that mirrors where it will be staged, and add one line to `EMITTERS`, its token to the module. `emit_stub_cpp.py` and `emit_binding_cpp.py` are the worked examples; a Rust stub is the next of that shape.
- A per-API hooks module beside the definition is reserved for peculiarities. Its interface is deliberately undefined until the first real case shows what it needs; the model is plain data so a hook can adjust it without the generator knowing why.
