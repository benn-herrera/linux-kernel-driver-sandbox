# ARCHITECTURE – api_gen

How this implementation meets SPEC.md. Standard-library Python, 3.11 or later for `tomllib`, run inside the build container; where it runs and what consumes its output is in the root ARCHITECTURE.md, "API generation".

## Shape

One pass, three stages, no state between runs:

```
definition ──load──▶ Api (frozen dataclasses) ──each selected emitter's validate──▶ selected emitters ──▶ files
```

- `model.py`: `load()` reads the TOML and `from_dict()` turns it into an `Api`. Every language-independent rule in SPEC.md "The definition" is enforced here: identifier syntax, no leading `_` on a name, uniqueness, ranges (every untyped constant, its literal terms and its sum fit its group's `_base_type`, every enum entry its enum's), references (a sum's terms share its base type), lifecycle shape, where `_optional` may appear (only on a parameter with a `_ref`, and on `memory` only with `_ref = "in"`), what a literal sum term may be (parsed once, by `_term()`), and which strings may be emitted inside a string literal (`check_literal_text()`, also applied to `--library`). Failures raise `DefinitionError` with a message that names the table and key; the loader stops at the first.
- `naming.py`: every SPEC.md "Naming" rule as a pure function of namespace and name, among them `lua_to_string()`, a conversion's Lua name, and `unknown_value_name()` and `NO_FLAGS`, the texts a conversion returns for a value with no entry and for a zero bit value; `BUILTIN_C_TYPES`, the one map from a builtin type to its C spelling that the model and every emitter read; and `BASE_C_TYPES`, the one map from a `_base_type` to its C type, `<stdint.h>` constant macro and value range, so a new base type is one row; the loader's range checks and the Lua emitter's signed-flag check read the range from it. Emitters never build a generated name by string concatenation of their own.
- `emit_c.py`, `emit_cpp_wrapper.py`, `emit_lua.py`, `emit_cpp_stub.py`: one module per output, each exposing `validate(api)`, which returns every objection that output has as a message prefixed with the output's name (`header:`, `wrapper:`, `lua:`, `stub:`), and one emit function taking the `Api` and returning the file's text. A language's facts live in its emitter: its keyword table and whatever it alone would refuse. An emit function assumes its `validate` returned nothing and does not check again. They share the model and `naming` and nothing else, except that the Lua emitter calls `emit_c.cdef()`, so the FFI declarations and the header are one rendering of the same structs and functions, and the other emitters call `emit_c.c_type()`, `param_type()`, `c_params()` and `param_list()` so every signature matches the header's; `c_params()` is the one place a `memory` parameter becomes its pointer and count pair, and `param_list()` the one place its `(type, name)` pairs join into a signature's parameter list text.
- `__main__.py`: the command line. Parses arguments, loads, runs each selected emitter's `validate` and reports every objection at once, one line each; a message several emitters raise identically prints once, its line naming every one of them, comma-joined in `EMITTERS` order (`header, wrapper, stub: ...`). It then runs the selected emitters in memory and writes, so a failing definition leaves no partial output. `output_paths()` is the one function that names the outputs, keyed by the output tokens `h`, `hpp`, `lua` and `stub_cpp`: its keys are the vocabulary `--outputs` accepts (`TOKENS`), and `EMITTERS` and the render table in `_generate_main()` are keyed the same way; generation and `gendeps` both call it. It always writes what is selected; whether it runs at all is make's decision, from the definition's mtime. Its `gendeps` mode prints the make rules `exercises/gen.mk` includes, from the one function that names the outputs, so the naming rule has a single home and the build file carries none of it. `exercises/gen.mk` passes its `OUTPUTS` variable, all four tokens unless the exercise's `api_def/Makefile` sets it before the include, to `gendeps` as `--outputs`, and the fragment's rule carries the same selection into generation. `adef.mk` is remade only when the definition changes, and a dropped output's file stays under the generated directory, so a changed `OUTPUTS` needs `userspace-clean-vdev`; `gen.mk` says so beside the variable.

## The model

`Api` is a frozen dataclass tree whose every item is a `Node`, a keyword-only base carrying `name` and `docstring`: `Group` of `BitConst`, of plain constants as `EnumEntry`, or of `StringConst`; `TypedConst` of `EnumEntry`; `OpaqueRef`; `Struct` of `Field`; `Function` of `Param`. `Api` itself and its optional `DriverData` are not nodes. Tuples throughout, in document order. Each of the three untyped-constant kinds (bit, plain, string) is an array of `Group`s, each carrying a docstring and a base type (`None` for a string group), for the emitters that render one block per group; a group has no name in the definition, so its `name` is where it is, `untyped_const[0]`; `Api.bit_consts`, `Api.consts` and `Api.string_consts` are every entry across a kind's groups in order, for everything that treats constants one by one: literal values, composition, uniqueness, pins. A composed entry (a list of terms, each an earlier same-table entry or a literal integer) carries both its resolved `value` and its `parts` in the order written, each the entry's name or a `LiteralTerm` holding the literal's value and the base it was written in, since the header renders a sum symbolically from `parts` while every other emitter uses `value` directly; no emitter parses a term again; the loader refuses a bit-group sum whose terms share a bit, and any sum with a term of another base type. `Api.constant_names()` lists every constant, enum entries included, with where it is written, for the loader's uniqueness check and the header's macro check. A bit or plain `Group` and a `TypedConst` carry `to_string`, the `_to_string` name or `None`; a string group's is always `None`, since the loader refuses the property there as an unknown key. `single_bit_entries()` is the one statement of which bit entries a conversion decomposes a value into, read by both emitters that render one. `Api.kind()` answers the one question every emitter asks, which category a type name belongs to, from the validated tree rather than by re-checking. `Api.names()` lists every name the definition gives with where it is written, `_to_string` names included (`typed_const.result._to_string`, `untyped_bit_const[0]._to_string`), so each emitter's `validate` checks its own keywords over one walk of the tree.

Normalisation happens on the way in. A described item's `_` properties are split from its members first, so no member check ever sees a property. `_attributes()` turns a naked value into the table it is sugar for, so a bare type string and a `{ _type, ... }` table become the same `Param` or `Field`, and a bare integer and a `{ _value, _format, _docstring }` table the same `EnumEntry`; `tomllib` already makes a nested `[a.b.c]` table and an inline one the same dict. `Param.ref` is `None` or one of `in`, `out`, `inout`; `Param.count_type` is set for `memory` only. Emitters see one shape.

Order is document order because `tomllib` builds insertion-ordered dicts, a guarantee Python makes since 3.7 that the TOML specification does not. The loader's docstring states the reliance; it is the one place the project depends on it.

## Emitters

- **Header** (`emit_c.header()`): `validate()` refuses a C keyword as any name, a typed enum entry above the `i32` maximum (a C17 enumerator is an `int`, whatever the enum's base type), and a constant whose C name is one of `header_macros()`, the set of macros the header defines or tests for itself, defined beside `header()`. Renders the blocks in SPEC.md order. `declarations()` renders opaque refs, structs and functions and takes the function prefix as an argument, so the header passes `NS_API ` and the cdef passes nothing, and `constants=False` for the cdef. `_constant_group()` renders a bit or plain group as its run of macros, and `_sum()` a composed entry from `parts`; `typed_literal()` is the one spelling of a value as a constant of its base type, the sign outside the macro, used for a group's values, its literal terms and a negative enum entry. The C++ wrapper's constants are `auto` from these macros, so the header is the one place a constant's type is spelled. Type mapping is `c_type()` and `param_type()`. The ABI pins are one trailing `#if defined(NS_IMPL)` block from `DriverData`, includes and `static_assert` lines, after every constant they name; `cdef()` does not render it.
- **Lua module** (`emit_lua.module()`): `_constant_sections()` renders every constant from the model's already-resolved `value` — a composed entry's sum, overlap-checked for a bit group, is computed once in `model.py`, not recomputed here — so the numbers come from the model and not from the FFI. `_class()` builds one class per opaque ref that declares a `_ctor`, from the `_ctor`, `_dtor` and `_class` the definition states; nothing about the class is inferred from names or shapes. `_marshal()` turns a parameter list into four lists at once: the Lua arguments, the C call arguments, the cdata allocations for non-memory reference parameters (copied in from the argument for `in` and `inout`, zeroed for `out`), and the values returned for `out` and `inout`; a `memory` parameter is a Lua string — `in` passed straight through with its length as the count, `out` and `inout` each allocated into a buffer that is returned as a string via `ffi.string`. The constructor uses the same arguments, call and allocations. `_lookup()` renders an enum's or plain group's conversion as a table keyed by value, deduplicated in Python so the last entry wins, and `_bit_to_string()` a bit group's with the `bit` library, bound as a module local only when a bit group has a conversion. `validate()` refuses a Lua keyword as any name, a bit flag above the `i32` maximum (LuaJIT's `bit` operations are signed 32-bit), a parameter named like one of `GENERATED_NAMES` (every free name the generated text binds or references where a class function's arguments are in scope, a module-level tuple beside the templates), a member that would collide with `new`, `_handle`, a method or a cached `out`, and a module field defined twice — a constant, a conversion under its rendered name from `_conversion_names()`, `raw`, or a class — naming both definers.
- **C++ wrapper** (`emit_cpp_wrapper.wrapper()`): an enum's conversion is rendered after its `enum class` by `_enum()`, a plain group's after its constants by `_plain_to_string()`, both through `_switch()`, and a bit group's after its constants by `_bit_to_string()`; `<string>` and `<charconv>` are included only when a group's conversion needs them. `validate()` refuses a C++ keyword as any name, from `CPP_KEYWORDS`, which holds the C keywords C++ shares since the wrapper includes the header, a parameter named like one of its own `GENERATED_NAMES` (every free name the class's generated text binds or references where a parameter is in scope, a module-level tuple beside the templates), and a name defined twice in the namespace, an enum class or a class, naming every definer. The namespace list holds each group's conversion name and each distinct enum conversion name once, so enums sharing a name overload rather than collide, while an enum's conversion named like a group's is still a duplicate.
- **Stub** (`emit_cpp_stub.stub()`): `validate()` refuses only a C++ keyword, from `emit_cpp_wrapper.cpp_keyword_objections()`, the wrapper's own check shared rather than duplicated. Every body is `return {};`, which C++ value-initialises to the return enum's zero entry; the stub has no need of a failure result to pick.

## What the emitters cannot express

- `_optional` is documentation only in the C header, which has no expression for it; the C++ wrapper and the Lua module both render it, as an optional pointer parameter and as a nil-admitting argument respectively.
- The spelling of numbers as written. `tomllib` yields integers, so the definition says `_format = "hex"` where it wants hex; without it a value is decimal whatever the file said.

## Tests

`tests/test_model.py`, `tests/test_header.py`, `tests/test_lua.py`, `tests/test_cpp_wrapper.py`, `tests/test_cpp_stub.py` and `tests/test_cli.py` cover the generator's outputs by name — the loader's rules, the C header, the Lua module, the C++ wrapper, the C++ stub, each emitter's `validate` in its own file, and generation plus `gendeps` — standard `unittest` over a small fixture definition in a namespace of its own, so a test failure is about the generator and not about `tiny_compute`; each SPEC.md contract line has a test, and a line without one is a gap to close; `just api-gen-test-vdev` runs them in the container, the only place they run; `tests/test_compiled.py` compiles the header as C and C++, builds and runs the fixture's fake library under the C++ consumer and the Lua module under `luajit`, drives the `gendeps` fragment through `make -n`, and round-trips every exercise's definition, against the container's pinned clang and luajit; `tests/support.py` is the home of `FIXTURE`, `KITCHEN_SINK`, `MINIMAL` and the helpers.

The end-to-end check is the project's own loop: `just test` generates from the real definition, builds the library against the generated header with the pins active, builds the test program, and runs the Lua test through the generated module in the guest.

## Extension points

- A new output is a new `emit_*.py` taking the `Api`, plus its token: one key in `output_paths()`, naming a path under the output directory that mirrors where it will be staged, and the same key in `EMITTERS` and the render table in `__main__.py`. `emit_cpp_stub.py` and `emit_cpp_wrapper.py` are the worked examples; a Rust stub is the next of that shape.
- A per-API hooks module beside the definition is reserved for peculiarities. Its interface is deliberately undefined until the first real case shows what it needs; the model is plain data so a hook can adjust it without the generator knowing why.
