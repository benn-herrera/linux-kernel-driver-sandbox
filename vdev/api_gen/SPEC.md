# SPEC – api_gen

The consumer-facing contract of the API generator: what a definition may say, and what every compliant implementation produces from it. How this implementation does so is in ARCHITECTURE.md beside this file. Where the generator sits in the build is in the root ARCHITECTURE.md, "API generation".

## Purpose

A userspace API is stated once, in a definition file, and every artifact a consumer needs is generated from it: a C header that also carries, for the implementation's build only, the wrapped API's header and a compile-time check that the constants pinned to it agree; a header-only C++ wrapper; a LuaJIT module; a Rust binding; a Rust ABI relay, which exports the C ABI from a Rust implementation; and implementation stubs in C++ and Rust. The definition is the source of truth; the artifacts are build products and are never edited. The definition states meaning, not shape: each output is idiomatic for its own language, and no output copies another's form. The implementation is a Linux shared object, `lib<name>.so`, which the Lua module loads and the Rust binding links by the file name `_general._bound_library` gives.

## The definition

One TOML file whose name ends in `.adef.toml`, the rest of it free: the outputs take their names from `_general._name`, never from the file's.

Every key that is not a name begins with `_`, at every level: every other key is a member name (a constant, field or parameter), and no member name begins with `_`. `[_general]` describes no item, so every one of its keys is a `_`-prefixed property too. `[_wrapped_api]` describes no item either: it holds the properties `_headers` and `_pinned_value`, and the members of `_pinned_value` are names.

- Group and item properties: `_docstring` (documents the group or item it is on), `_return` (functions only), `_base_type` (enums, constant groups and boxed scalars only), `_to_string` (enums, bit and plain constant groups only), and on an opaque ref `_class`, `_ctor`, `_dtor`.
- Entry attributes: on a constant `_value`, `_docstring`, and for an integer `_format`; on a struct field `_type`, `_docstring`; on a parameter `_type`, `_ref`, `_count`, `_optional`, `_docstring`.
- A naked value is sugar: a constant `name = 4` (or `name = ["a", "b"]`) is exactly `name = { _value = 4 }`, and a field or parameter `name = "u32"` is exactly `name = { _type = "u32" }`. An inline table and a nested `[a.b.c]` table are the same thing; both are accepted everywhere.
- `_ref` states how the callee reaches a parameter: `"in"` is read by the callee, `"out"` is written by it, `"inout"` is both; absent means by value. A `memory` parameter requires `_ref`.
- `_count` is one of the unsigned integer types `"u8"`, `"u16"`, `"u32"`, `"u64"`, required on a `memory` parameter and allowed nowhere else: the type of the buffer's byte count.
- `_optional = true` marks an `in`, `out` or `inout` struct, boxed scalar or scalar parameter, or a `memory` parameter with `_ref = "in"`, as one whose null the caller may pass instead of a value; refused everywhere else, naming the parameter: on a parameter with no `_ref` (a by-value parameter has no null to pass) and on a `memory` parameter with `_ref = "out"` or `"inout"`. A constructor's cached `out` parameter (see the C++ wrapper and the Lua module below) ignores it, since the binding always supplies that parameter itself.
- `_format` is `"hex"` or `"dec"` (the default): how the number is spelled where a literal is emitted.
- `_to_string = "<name>"` asks for a function converting a value of the group to text, named `<name>` as each output's section below states; absent, no conversion is generated for the group. `<name>` is a name like any other: the identifier and keyword rules below apply to it. An enum converts a value to its entry's unprefixed name (`"ERR_TIMEDOUT"`), and a value no entry has to `UNKNOWN_<ENUM>` (`UNKNOWN_RESULT`). A plain group does the same, converting to the later entry where two share a value, with `UNKNOWN` for a value no entry has. A bit group decomposes the value: each entry with exactly one bit set, in document order, whose bit is present contributes its unprefixed name and removes its bit; the names are joined with `|`, and any bits left over follow as one final term, `0x` and their lower-case hex without padding; zero converts to `NONE`. A composed entry with more than one bit is never matched: with entries `a` bit 0, `b` bit 1 and `ab = ["a", "b"]`, 3 converts to `A|B`, 1 to `A`, 0 to `NONE` and 9 to `A|0x8`.

Every kind below but `[_general]` and `[_wrapped_api]` is an array of groups, `[[kind]]`: each group is a table whose `_`-prefixed keys are its properties and whose other keys are its members, and has at least one member, else it is refused as `<kind>[<i>]: has no entries`, `<i>` the group's index from 0. A constant kind's (`untyped_bit_const`, `untyped_const`, `string_const`) members are its constants. A named kind's (`typed_const`, `opaque_ref`, `boxed_scalar`, `struct`, `function`) members are its items, each `<name> = <table>`, the table the item's body, so a `[function.open]` written after a `[[function]]` header is the item `open` of that group; such a group's one property is an optional `_docstring`. An item body that is not a table is refused as `function.open must be a table`. An item's name is unique within its kind across every group: a repeat is refused against the later one, which is dropped, as `function.open: already defined in function[0]`, naming the first one's group. An objection names an item by kind and name whichever group holds it (`function.open`, `struct.stats.count`), and a group by its index (`function[1]: has no entries`, `function[1]._docstring must not contain a line break`, `function[1]: unknown key(s) _colour`). A group's docstring describes no item: each output renders it as a comment, where its section below states. A named kind's item written with no group, `[function.open]` with no `[[function]]` before it, makes `function` a single table, which is refused as `[function] must be an array of tables, [[function]]`.

The file holds these tables, each optional unless stated; any other top-level table is an error:

- `[_general]` (required): `_name` (an identifier, required; names every output, as `<name>` in each output's path below), `_namespace` (an identifier, required; the prefix for everything generated), `_version` (four integers 0..255, required, encoded most-significant first into one 32-bit value), `_bound_library` (the shared object file name the Lua module loads and the Rust binding links; a plain file name as written, no quotes, backslashes or control characters).
- `[[untyped_bit_const]]`: an array of groups of constants that are bit flags. Each group has an optional `_docstring`, an optional `_base_type`, an optional `_to_string`, and at least one entry. An integer value is a bit index whose flag is a positive value of the group's base type: 0..30 under `i32`, 0..31 under `u32`. A list sums its terms into the entry's value: each term is an earlier entry of this group or of an earlier group of the same base type, or a literal integer fitting the base type, written as a string in decimal or in hex with a lower-case `0x` prefix, either with an optional leading `-` and nothing else (`"4"`, `"-4"`, `"0x1f"`); any other term that is not an entry name is refused; the loader refuses a term naming an entry of another base type, naming both entries and both base types, and a sum whose terms share a bit, naming the two.
- `[[untyped_const]]`: an array of groups of plain integer constants, with the same group properties. A value is an integer fitting the group's base type (`i32`: -2^31..2^31-1; `u32`: 0..2^32-1), or a list summing the same kind of terms `untyped_bit_const` composes — an earlier entry of this group or of an earlier group of the same base type, or a literal integer fitting the base type — with that range applied to the sum; a term naming an entry of another base type is refused the same way. A floating-point value, or a `_base_type` of `f32` or `f64`, is refused as not implemented.
- `[[string_const]]`: an array of groups of string constants, each with an optional `_docstring` (no `_base_type`: a string has no fixed-width representation; no `_to_string`) and at least one entry. Values are strings containing no `"`, `\` or control character (U+0000..U+001F, U+007F).
- `[[typed_const]]`: an array of groups of enumerations, each item `<enum>` with an optional `_docstring`, `_base_type` and `_to_string`. Values are integers fitting the enum's base type.
- `[[opaque_ref]]`: an array of groups of handle types, each item `<name>` a handle type whose representation is the implementation's secret. It has no members, only properties: `_docstring`; and for bindings with object semantics, `_ctor`, the function that produces the handle (it has exactly one parameter of this type with `_ref = "out"`), `_dtor`, the function that releases it (its only parameter is this type by value; requires `_ctor`), and `_class`, the object's name in those bindings, written idiom-free (lowercase identifier; default the ref's name). Each binding applies its own casing.
- `[[boxed_scalar]]`: an array of groups of boxed scalars, each item `<name>` a distinct kind of integer, so that two quantities of the same width, a device offset and a byte count, cannot be passed one for the other. It has no members, only properties: `_docstring` and `_base_type` (required). A boxed scalar is a parameter type, by value or with any `_ref`, `_optional` as for a scalar, and a struct field type; it is not a `_return` type and takes no `_count`.
- `[[struct]]`: an array of groups of structs, each item `<name>` an optional `_docstring`, then fields in document order.
- `[[function]]`: an array of groups of functions, each item `<name>`: `_return` (a `typed_const` enum name whose entries include the value 0, required), an optional `_docstring`, then parameters in document order. A `memory` parameter `p` becomes, in the C header and every output that mirrors it, an adjacent pair: the pointer `p`, then its byte count `p_count` of the `_count` type. The definition does not write the count; a numeric parameter written beside a buffer is just another parameter.
- `[_wrapped_api]`: the wrapped API: its C headers, which the implementation includes, and the constants of this API pinned to those headers' macros. `_headers` (required) is a non-empty list of the wrapped API's header paths, each relative to the project directory, else `_wrapped_api._headers must be a non-empty list of strings`; each element is refused, naming it by its index, `_wrapped_api._headers[1]`, if it holds a quote, backslash or control character, if it is absolute or begins with `../`, and if an earlier element is the same path (`_wrapped_api._headers[1]: already listed`). `_pinned_value` is a table whose each member maps an `untyped_bit_const` key to the macro of those headers it must equal. Absent `[_wrapped_api]`, no output refers to a wrapped API; present without `_pinned_value`, or with it empty, the headers are still included and nothing is pinned.

`_base_type` is `"i32"` (the default) or `"u32"`, and chooses the fixed-width type of an enum or a group's constants: the C header types a group's constants by it, the C++ wrapper takes that type from the header, and the wrapper's enum classes and the Lua FFI declarations name it. On a boxed scalar it is the type of the one value the box holds, required and wider: any integer type, `i8` through `u64`; a floating-point type, `memory` or a definition's own type is refused.

Rules a definition must satisfy:

- Types are the integer types `i8`, `u8`, `i16`, `u16`, `i32`, `u32`, `i64`, `u64`, the floating-point types `f32`, `f64`, `memory`, or a name from `typed_const`, `opaque_ref`, `boxed_scalar` or `struct`. The builtins other than `memory` are variable types only: `_base_type` and `_count` take the values stated for them. Those four categories share one namespace; a name in two of them is an error, as is shadowing a builtin.
- A key beginning with `_` that is not recognised where it appears is an error naming the key and where; so is a key not beginning with `_` inside an entry's table or an opaque ref. A kind other than `[_general]` and `[_wrapped_api]` written as a single table is an error: each is an array of tables, `[[...]]`. A group has at least one entry.
- A `memory` parameter's `p_count` is not the name of another parameter of the same function.
- Every name is a C identifier that is neither a C, C++, Lua nor Rust keyword. No parameter is named like a name a binding's generated code itself uses where that parameter is in scope; each binding's section below says so.
- A composed constant names only entries defined before it, in its own group or an earlier one of the same `_base_type`. Its sum's running total, term by term in the order written, fits the base type at every step, not only at the end, naming the term after which it does not: a constant expression that overflows midway is a compile error in Rust and undefined in C. A pin names an existing `untyped_bit_const` entry. Constant names are unique across every constant group, the string constants, every enum, and the version constant; the C identifiers of enums, opaque refs and their tags, boxed scalars, structs and functions are unique together.
- Within one enum, no two entries share a value.
- Docstrings contain neither `*/`, `]]` nor a line break: the bindings, the Rust relay and the Rust stub render a docstring as a line comment, which a line break would end.
- Order is meaning: parameters, fields, groups and the items of a group appear in every output in the order written.
- A ctor has no `memory` parameter with `_ref = "out"` and no parameter with `_ref = "inout"`: the bindings cache every other `out` of the ctor on the object, a buffer has no owner there, and a constructor has nothing to return an updated value through.

## Naming

With namespace `ns`, upper-cased `NS`:

| definition | generated |
|---|---|
| bit, plain, string constant or enum entry `key` | `NS_KEY` in C; `KEY` in a module-scoped binding |
| `_general._version` | `NS_API_VERSION` |
| enum `e` | `enum ns_e`, typedef `ns_e` |
| opaque ref `h` | `struct ns_h_opaque`, typedef `ns_h` (a pointer) |
| boxed scalar `b` | `struct ns_b`, typedef `ns_b` |
| struct `s` | `struct ns_s`, typedef `ns_s` |
| function `f` | `ns_f` |
| `_to_string` `f` on enum `e` | `ns::f`, overloaded on `ns::E`, in C++; `M.e_f` in Lua; `E::f` in Rust |
| `_to_string` `f` on a bit or plain group | `ns::f` in C++; `M.f` in Lua; `f` in Rust |
| `memory` parameter `p` | `p`, then its byte count `p_count`; in the Rust binding and the Rust stub, one slice `p` |
| in C++: enum `e`, entry `k`, boxed scalar `b`, struct `s`, class `c` | `ns::E`, `E::K`, `ns::B`, `ns::S`, `ns::C` (UpperCamel) |
| in the Rust binding: enum `e`, entry `k`, boxed scalar `b`, struct `s`, class `c` | `E`, `E::K`, `B`, `S`, `C` (UpperCamel) at module scope |
| in the Rust binding: the local holding an enum parameter `p` reached through `_ref`, other than an `out` the caller receives | `p_raw` |
| in the Rust relay's `ffi` module: every constant and type; the relay's exported functions; in the Rust binding's `ffi` module: every type and function | its C name, as above |
| in the Rust relay and stub: the implementation of function `f` | `f` |
| in the Rust relay: the local a pointer parameter `p` reaches the implementation through | `p_local` |
| `_base_type` `i32`, `u32` | `int32_t`, `uint32_t` as a type; `INT32_C`, `UINT32_C` on a literal in the C header |
| visibility macros | `NS_C_API`, `NS_API`, with `NS_IMPL` as the implementation's define |

## Outputs

Every output starts with a banner naming its source and saying it is generated. Under the output directory: `include/<project>/` holds the headers and `binding/` the Lua module, each staged whole; `rust/` holds the Rust binding and relay, compile-time inputs a crate reaches from the directory the implementation's build names in `API_GEN_RUST_DIR` (or, for the binding, beside the crate root), never staged; `stub/` holds the implementation stubs, never staged.

Every Rust output is edition-agnostic: it compiles unchanged at edition 2021 and at edition 2024 with Rust 1.82 or later, spelling the forms both accept: `#[unsafe(no_mangle)]`, `unsafe extern "C"`, each unsafe operation inside an `unsafe fn` in an `unsafe { }` block of its own, and `core::convert::TryInto` by its path. It is `rustfmt`'s output under style edition 2024 and the default configuration (see "Invocation"). `Result` is spelled bare wherever a signature or a local's type names it; an enum's `TryFrom` spells `core::result::Result`. A function's doc comment is its docstring, then each parameter's docstring as `name: text`, then whatever lines the output adds, a bare `///` line separating the docstring from anything after it. A function the Rust stub renders with 8 or more parameters, and a Rust binding method or `create` whose parameters, `&self` counted, are 8 or more, carries `#[allow(clippy::too_many_arguments)]`: clippy's default lints refuse it otherwise.

### `include/<project>/<name>.h` — the C header

- For a consumer, includes only `<stdint.h>`. Its preprocessor content is: `#pragma once`, that include, the two blocks defining `NS_C_API` (`extern "C"` under C++) and `NS_API` (`NS_C_API` plus default visibility when `NS_IMPL` is defined), one `#define` per bit or plain constant and for the version, and the implementation-only blocks below. No macro is used in any declaration except `NS_API` before each function.
- One block at the end of the file under `#if defined(NS_IMPL)`, and so only in the implementation's build: one include per element of `_wrapped_api._headers`, in list order, as `"<project>/<header>"`, the project name joined to the element, then an include of `<assert.h>`, then one file-scope `static_assert(NS_KEY == MACRO, "...")` per pin, none where `_pinned_value` is absent or empty. The library failing to compile is the ABI check; a consumer never sees the wrapped API's header. Absent `[_wrapped_api]`, the block is not emitted.
- The version and every bit and plain constant are object-like macros, `#define NS_KEY <value>`, each typed by its `<stdint.h>` constant macro. The version is `UINT32_C(0x...)`, its four bytes as eight hex digits. In a group, the base type's macro (`INT32_C` for `i32`, `UINT32_C` for `u32`) wraps a literal value, spelled per `_format`, and a single bit's one: `INT32_C(16)`, `UINT32_C(0xbeef)`, `(INT32_C(1) << n)`. A negative value keeps its sign outside the macro, which wraps its magnitude, `(-INT32_C(0x5))`; the base type's minimum, whose magnitude the type cannot hold, is `(-INT32_C(0x7fffffff) - 1)`, spelled per `_format` the same way. A composed entry's sum is symbolic and parenthesised, `(NS_A | NS_B)` in a bit group and `(NS_A + NS_B)` in a plain group, a literal term rendered as a literal value is, in the base it was written in, `(NS_A | INT32_C(4))`, `(NS_A + (-INT32_C(0x3)))`. Each group is one run of macros under its docstring comment. Each typed enum is an enum with explicit values and a typedef, a non-negative value spelled per `_format` and a negative one as a negative group value is. Each string constant group is a run of `static const char NS_KEY[] = "...";`.
- Each opaque ref is an incomplete struct and a pointer typedef. Each boxed scalar is a struct of one member, `typedef struct ns_b { T value; } ns_b;` with `T` its `_base_type`'s C type, under its docstring comment, after the opaque refs and before the structs, so that a struct may hold one; C passes and returns it by value, a type distinct from every other. Each struct has its fields in order with a typedef.
- Functions are declared in document order. Type mapping: an integer type `iN` → `intN_t` and `uN` → `uintN_t`, `f32` → `float`, `f64` → `double`, an enum, boxed scalar or struct by its typedef, an opaque ref by value as its typedef; a non-memory type `T` with `_ref = "in"` → `const T*`, with `"out"` or `"inout"` → `T*`; `memory` → `const void*` when `"in"`, `void*` when `"out"` or `"inout"`, followed by `p_count` of its `_count` type.
- Docstrings become `/* */` comments: above a constant group, enum, struct, opaque ref or function, trailing a constant, enum entry or struct field; a parameter's docstring joins its function's comment as `name: text`.
- A named kind's group docstring is a `/* */` comment line above the first of the group's items, its enum, opaque ref, boxed scalar, struct or function declaration, and above that item's own comment.
- The header carries no `_to_string` conversion.
- A constant of any kind, an enum entry included, whose C name is one of the header's own macros, `NS_C_API`, `NS_API`, `NS_IMPL` or `NS_API_VERSION`, is refused, naming the constant and the macro.
- A typed enum's entries are C enumerators whatever the base type, and a C17 enumerator is an `int`: an entry whose value exceeds the `i32` maximum, as `u32` otherwise allows, is refused, naming the entry.
- A parameter named like a type the declarations spell, a fixed-width integer type or one of the header's typedefs, is refused, naming the parameter: in a prototype the name hides that type from every parameter after it. The C++ wrapper and the C++ stub, which declare the same signatures, refuse it too.
- The header is not a binding input. The Lua module carries its own FFI declarations, rendered from the same definition, so nothing parses the header at run time and the implementation-only blocks may hold whatever the check needs.

### `include/<project>/<name>.hpp` — the header-only C++ wrapper

A C++20 header beside the C header, including it and nothing but the standard library, inside `namespace <ns>`. Constants are `inline constexpr` under their unprefixed names, each constant group — bit, plain or string — one run under its `_docstring` as a `//` line: the version and every bit and plain constant `auto`, initialised from its header macro and so typed as the header types it, a string constant `const char*`; each enum is an `enum class` over the C values with its base type as the underlying type and UpperCamel entries; each `_to_string` conversion is an `inline` function under the namespace — an enum's `const char* f(E value)`, a `switch` over the enum class, so enums may share `f` as overloads; a bit or plain group's `std::string f(T value)`, `T` the group's base type, following the group's constants; each boxed scalar and each struct is an alias of the C typedef, `using Offset = xy_offset;`, a boxed scalar's alias adding no operator or conversion, so the caller constructs one with braces, `Offset{base + 4096}`, and a method takes it by value or by reference as the C signature does. Each opaque ref with a `_ctor` is a class named from `_class` in UpperCamel, move-only (move assignment releases the current handle first): `create(...)` takes the `_ctor`'s parameters other than its non-memory `out`s and returns the class by value, with the call's result written through an optional out-pointer; on failure the object is falsy (null handle, value-initialised members), so `if (!dev)` is the check and no optional is involved; every other `_ctor` `out` is a private member read through a const accessor named after its parameter, `dev.info()`; the destructor and `release()` call the `_dtor`; one method per function, other than the `_ctor` and `_dtor`, whose first parameter is the opaque by value, returning the enum and taking a `memory` parameter as the C header does, pointer then count. A non-memory `in` is `const T&` (a boxed scalar or struct by its alias), an `out` or `inout` `T&`, each passed to C by address; an `_optional` struct or scalar `in`/`out`/`inout` method parameter is `const T*` or `T*` instead, forwarded as-is, defaulted to `nullptr`; defaults are trailing, so an `_optional` parameter followed by a non-optional one keeps the pointer type but has no default. A constructor's cached `out` parameters ignore `_optional`. An opaque by value is the C handle type; an enum reached through `_ref` is the C typedef. Results are `[[nodiscard]]`. Casts are functional-style, C names unqualified, fixed-width integers spelled as the C header spells them. No exceptions; no allocation but the `std::string` a group's conversion returns. A name defined twice in the namespace, among the constants under their unprefixed names, the enum classes, the boxed scalar and struct aliases and the classes, is refused, naming every definer, as is an entry an enum class defines twice under its UpperCamel name (`err_busy` and `err__busy` are both `ErrBusy`). A conversion name the namespace already defines is refused, as is one two conversions share unless both are enums'. A parameter the class renders, each of the `_ctor`'s and each method's but its first, named like a name the class's own code uses beside it (`create()`'s `result` and `status`, the private constructor's `handle`, the `handle_` member, and every name it renders from the definition there: the C functions and typedefs, the fixed-width integer types, and the namespace's enum classes, struct aliases and classes) is refused, naming the parameter; so is a method named like one of the rendered names, and a method or cached `out` named like another member or like the class's own name, `create`, `handle`, `handle_`, or `release` where a `_dtor` generates it. A named kind's group docstring is a `//` line above the first of the group's enum classes, aliases or classes, and in a class above the first of the group's functions the class renders as `create`, a method or `release`.

### `rust/<name>.rs` — the Rust binding

A Rust module file, the root of a crate or a module a crate declares, as `mod <name>;` beside its root or around `include!(concat!(env!("API_GEN_RUST_DIR"), "/<name>.rs"))`, needing nothing but `core` and the prelude. After the banner, in order, each block separated from the next by a blank line:

- `pub mod ffi`, under `#![allow(non_camel_case_types)]`: each enum's C name aliasing its base type, and each opaque ref, boxed scalar and struct exactly as the Rust relay below defines them; then one `unsafe extern "C"` block under `#[link(name = "<lib>")]`, `<lib>` the library file name (`_general._bound_library`, or `--library`) without its `lib` prefix and `.so` suffix, declaring every function in document order as `pub fn` with the relay's parameter names, types (unqualified, the `ffi` module being their home) and doc comment (see "Outputs"). No constant is declared there.
- The version, each bit group, each plain group and each string group as the relay's `ffi` module renders them, under their unprefixed names (`pub const FEAT_A: i32 = 1 << 0;`, `pub const FEAT_AB: i32 = FEAT_A | FEAT_B;`). A group's `_to_string` conversion follows its constants: a plain group's `pub fn f(value: T) -> &'static str` and a bit group's `pub fn f(value: T) -> String`, `T` the group's base type, converting as "The definition" states.
- Each enum as `#[repr(T)] pub enum E`, deriving `Clone, Copy, Debug, PartialEq, Eq`, its entries UpperCamel with their C values; then `impl core::convert::TryFrom<T> for E`, `Err(raw)` for a value no entry has; then, with `_to_string = "f"`, `impl E { pub fn f(self) -> &'static str }`, the entry's unprefixed name, and `impl core::fmt::Display for E` writing that same text, so `format!("{}", e)` is it.
- Each boxed scalar, then each struct, re-exported under its UpperCamel name, `pub use ffi::xy_offset as Offset;`: the safe type is the FFI type, so a boxed scalar is built as `Offset(1 << 40)` and read through `.0`.
- For each opaque ref with a `_ctor`, a class `pub struct C`, named from `_class` in UpperCamel, holding the handle and each other `out` of the `_ctor` privately, and not `Clone`:
  - `create(...)` takes the `_ctor`'s parameters other than its non-memory `out`s and returns `Result<C, R>`, `R` the `_ctor`'s return enum, `Err(result)` on any result but the zero-valued entry. `handle(&self)` returns the `ffi` handle. Each cached `out` is read through a method named after its parameter, a struct by reference and anything else by value; the cached `out`s ignore `_optional`.
  - One method per function, other than the `_ctor` and `_dtor`, whose first parameter is the opaque by value, in document order, taking `&self` and the other parameters but the non-memory `out`s that are not `_optional`, and returning `Result<O, R>`: `O` is `()`, the one such `out`, or a tuple of them in order.
  - With a `_dtor`, `release(self)` consumes the object, calls it and returns as a method does, and dropping an object not released calls it on a non-null handle, discarding its result. Without one, neither exists.

### `rust/<name>_abi.rs` — the Rust ABI relay

The C header's ABI exported from a Rust implementation, regenerated with every generation and never edited: each exported function relays its call to a hand-written implementation function. A crate includes it inside a module it declares, `pub mod abi { include!(concat!(env!("API_GEN_RUST_DIR"), "/<name>_abi.rs")); }` as the stub below does, `API_GEN_RUST_DIR` being the absolute path of the generated `rust/` directory, supplied by the implementation's build; the file has no inner attribute at its top level, where `include!` refuses one. The crate root defines or re-exports `fn f` for every function; its visibility is the implementer's. After the banner, in order, each block separated from the next by a blank line:

- `pub mod ffi`, under `#![allow(non_camel_case_types)]`, the header's constants and types under their C names:
  - The version, `pub const NS_API_VERSION: u32 = 0x...;`, its four bytes as eight hex digits.
  - Each bit group, then each plain group, as one run of `pub const NS_KEY: T = <value>;`, `T` the group's `_base_type` (`i32` or `u32`): a single bit as `1 << n`, a literal spelled per `_format` with its sign in front (`-0x5`, `-0x80000000`), a composed entry's sum symbolic and unparenthesised, a literal term rendered as a literal value is (`NS_A | NS_B`, `NS_A | 4`, `NS_A + -3`).
  - Each enum as its C name aliasing its base type, `pub type ns_e = i32;`, then its entries as `pub const NS_KEY: ns_e = <value>;`.
  - Each string group as a run of `pub const NS_KEY: &str = "...";`.
  - Each opaque ref as its C name aliasing a pointer, `pub type ns_h = *mut ns_h_opaque;`, and the `#[repr(C)]` zero-sized struct it points to; any C caller can forge a handle, so the implementation validates a handle it is given before dereferencing anything behind it; each boxed scalar as a `#[repr(transparent)]` newtype, `pub struct ns_b(pub T);`; each struct as a `#[repr(C)]` struct of `pub` fields in order. A boxed scalar derives `Clone, Copy, Debug, Default, PartialEq, Eq, PartialOrd, Ord, Hash`, a struct `Clone, Copy, Debug, Default, PartialEq`, since a struct may hold a float.
- Each enum, then the re-exports, byte for byte as the Rust binding renders them: `#[repr(T)] pub enum E` with its `TryFrom`, and its conversion and `Display` where it has `_to_string`; `pub use ffi::ns_b as B;` per boxed scalar and struct. No unprefixed constant, group conversion, class or `Drop`.
- Where some parameter is `memory`, the private count check `c_len`, which takes a count to a slice length, `None` below zero or above `isize::MAX`; then a private buffer helper per `memory` direction some parameter has, each taking its count through `c_len` before it tests the pointer: `c_bytes` for `in`, `c_bytes_mut` for `inout`, `c_bytes_zeroed` for `out`.
- One `#[unsafe(no_mangle)] pub unsafe extern "C" fn ns_f` per function in document order, with the header's parameter names, its body calling `crate::f` through the pin below. Type mapping: a builtin by its own name (`u32`, `f64`); an enum, opaque ref, boxed scalar or struct by its C name in `ffi`, `ffi::ns_x`, the return type included; a non-memory type `T` with `_ref = "in"` → `*const T`, with `"out"` or `"inout"` → `*mut T`; `memory` → `*const core::ffi::c_void` when `"in"`, `*mut core::ffi::c_void` otherwise, followed by `p_count` of its `_count` type. Its doc comment is the function's (see "Outputs"), adding one `name: may be null` line per `_optional` parameter in order, then a `# Safety` section: `Every pointer argument must be null or valid for the call as the C header declares it, no buffer may overlap another argument of the same call, and no other thread may read or write a buffer argument during the call. A panic in the implementation aborts the process.`
- When `[_wrapped_api]` is present, the wrapped API and its pins: a `pub mod wrapped_api`, public so the implementation reaches the wrapped API's constants and structures through `abi::wrapped_api` without a second rendering of its headers, under `#![allow(dead_code, non_camel_case_types, non_snake_case, non_upper_case_globals)]` whose body is `include!(concat!(env!("OUT_DIR"), "/wrapped_api.rs"));`, `wrapped_api.rs` being `bindgen`'s rendering of the headers `_wrapped_api._headers` names, which the implementation's build writes into `OUT_DIR` (a cargo crate's `build.rs`, the cargo idiom); then one `const _: () = assert!(ffi::NS_KEY as i64 == wrapped_api::MACRO as i64, "NS_KEY must match MACRO");` per pin, both sides widened to `i64`, none where `_pinned_value` is absent or empty. The implementation failing to compile is the ABI check. Absent `[_wrapped_api]`, the file names no `wrapped_api`.

The implementation function is `fn f(<params>) -> Result<(), R>`, `R` the return enum, its parameters as the Rust stub below spells them. Each relay function pins the implementation to its exact signature through a `fn` pointer before calling it, `const IMPLEMENTATION: fn(<params>) -> Result<(), R> = crate::f;` under `#[allow(clippy::type_complexity)]`: a borrow that outlives the call, an `unsafe fn`, or a changed signature is a compile error naming the function. The ABI edge receives untrusted values; the relay forms no reference into caller memory except the slices it hands over, none of which the pin lets the implementation keep past the call, and never panics:

- A non-memory pointer reaches the implementation as `Option<&T>` (`in`) or `Option<&mut T>` (`out`, `inout`), `None` exactly when the pointer is null, whether or not `_optional`. `Some` points at a relay-owned local, `p_local`: for `in` and `inout` read from the pointer before the call by `read()`, which forms no reference, for `out` starting as `T::default()` (a handle as null). After the call returns, whatever it returned, the relay writes every non-null `out` and `inout` back from its local, in parameter order.
- A `memory` parameter reaches it as `Option<&[u8]>` (`in`) or `Option<&mut [u8]>` (`out`, `inout`), `None` for a null pointer or a count above `isize::MAX`, an empty slice for a non-null pointer with count 0. An `out` buffer is zero-filled before the slice is formed, since the caller's memory may be uninitialised; an `inout` buffer arrives initialised by contract and is not touched.
- An enum by value or through `_ref` stays its base integer, `ffi::ns_e` (`Option<&ffi::ns_e>`, `Option<&mut ffi::ns_e>`): a C caller may pass a value no entry names and the relay cannot answer for it; `E::try_from` is there for the implementation. An opaque ref by value or through `_ref` is the raw handle type, `ffi::ns_h`: the implementation owns handle semantics. A boxed scalar or struct by value is itself; a builtin itself.
- `Ok(())` returns the zero-valued entry and `Err(e)` returns `e as ns_r`, so an implementation behind the relay returns named entries only. A panic in the implementation aborts the process: an `extern "C"` function does not unwind.

Every constant is `pub`. A constant group's docstring is a `//` line above its run, and a named kind's group docstring a `//` line above the first of the group's items in each block that renders them, the `ffi` enum aliases and type definitions, the enums, the re-exports and the exported functions; every other docstring is a `///` line above its item. The file compiles, included by the stub, as a `cdylib` under `rustc -D warnings` at editions 2021 and 2024 with `API_GEN_RUST_DIR` and `OUT_DIR` supplied, clean under clippy's default lints. Refused, each naming what it names: a Rust keyword of edition 2021 or 2024, strict, reserved or weak (`crate` and `gen` among them), and an enum, entry, boxed scalar or struct name whose UpperCamel rendering is one; a field, enum `_to_string` conversion, parameter, or `p_count` or `p_local` derived from a parameter `p`, that rustc's `non_snake_case` lint refuses, one holding an uppercase letter or `__` once its leading and trailing `_` are trimmed (an exported function's name, and so the namespace, is exempt from the lint); a struct field of opaque type, as not implemented, since the structs derive `Default` and a raw pointer has none; a non-memory `out` or `inout` parameter named `result`, the local the implementation's result is bound to before the write-backs name each such parameter, and a parameter named `q_local` for another pointer or `memory` parameter `q` of its function; and a name defined twice at module scope (an enum, a re-export, `c_len` or a buffer helper, an exported function, or one of the prelude's names the file spells unqualified, `Err`, `None`, `Ok`, `Option`, `Result`, `Some`) or in an enum (an entry, `try_from`, its conversion), naming every definer.

### `binding/<name>.lua` — the LuaJIT module

A module returned from `require`, needing no file at run time:

- Its `ffi.cdef` text holds only what calls need: `typedef int32_t ns_e;` for each enum (`uint32_t` under `_base_type = "u32"`), the opaque, boxed scalar and struct declarations, and the functions without `NS_API`. No constants are declared to the FFI.
- Every constant is a Lua literal, `M.KEY`, with the same value the header gives it: the module is the namespace, so the `NS_` prefix is not repeated. A named kind's group docstring is a `/* */` comment line above the first of the group's items in `ffi.cdef`, and a `--` line above the first of its enums' literals, of its functions in `M.raw`, of its classes, and in a class of its functions the class renders as `new`, a method or the `_dtor`'s method.
- A bit flag whose value exceeds 2^31-1, as a `u32` group's bit 31 does, is refused: LuaJIT's `bit` operations are signed 32-bit, so the flag would not equal its own masked result.
- Each `_to_string` conversion is a module function taking the value, an enum's `M.<enum>_<f>(value)`, since Lua has no overloading, and a bit or plain group's `M.<f>(value)`. - A parameter the class renders, each of the `_ctor`'s and each method's but its first, becomes a Lua local of its class function, so one named like a name the module uses where it would be in scope (the module's locals `M`, `ffi`, `lib`; the globals it calls, such as `assert`, `type` and `tonumber`; a class function's own locals, such as `self` and `result`) is refused, naming the parameter.
- `M.raw.<f>` is the FFI function for each function.
- For each opaque ref with a `_ctor`, a class `M.<Class>`, the `_class` attribute in UpperCamel with no namespace prefix:
  - `new(...)` takes the `_ctor`'s parameters other than its non-memory `out`s, in order; returns `nil, result` on any result other than the enum's zero-valued entry, else an object whose `_handle` is the opaque value with the `_dtor` as its GC finalizer, and which caches every other `out` of the `_ctor` under that parameter's name: a struct as a plain table copy of its fields (`i64` and `u64` fields as cdata, every other builtin and enum field as a number, nested structs copied the same way, a boxed scalar field as a copy of its FFI struct), an `i64` or `u64` scalar as cdata, any other builtin or enum scalar as a number, a boxed scalar as its `_base_type`'s value would be.   - One method per function, other than the `_ctor`, whose first parameter is the opaque by value, taking the other parameters except non-memory `out`s, in order.   - A boxed scalar never reaches the caller as its box: the caller passes its `_base_type`'s value, a number or for `i64` and `u64` the cdata integer the module accepts there, and the method builds the FFI struct for the call, `ffi.new("ns_b", value)`; an `out` or `inout` is returned as that value, read from the struct's `value`, exactly as its `_base_type` is returned. ## Invocation

Two modes. Generation: `python3 -m api_gen <definition> --generated <dir> --project <name> [--library <file>] [--outputs=<list>]`. `--outputs` names the outputs to produce as a comma-separated list of tokens: `h` (the C header), `hpp` (the C++ wrapper), `lua` (the Lua module), `stub_cpp` (the C++ implementation stub), `rs` (the Rust binding), `abi_rs` (the Rust ABI relay), `stub_rs` (the Rust implementation stub); absent, all of them. An unknown or repeated token is a usage error, exit status 2 with a message listing the valid tokens. No output implies another: the wrapper and the C++ stub include the header, and the Rust stub the relay, but selecting them neither adds `h` or `abi_rs` nor requires it. `--library` overrides `_general._bound_library`, is held to the same rule and must not be empty, each objection to it reported beside the definition's loader objections; one of them must be present when `lua` or `rs` is selected, else the objection is `lua, rust: no library named; set _general._bound_library or --library` under the selected ones' labels, and with `rs` selected it is of the form `lib<name>.so`, `<name>` holding no `/` or whitespace, the one file name `#[link(name = "<name>")]` finds. Generating `rs`, `abi_rs` or `stub_rs` runs `rustfmt --edition 2024 --config-path /dev/null`, whose output the file is, so no `rustfmt.toml` beside, above or outside the definition, the user's own included, reaches it; without `rustfmt` on `PATH` generation exits 2 with `api_gen: rustfmt is required for the Rust outputs and was not found on PATH`, and a failing `rustfmt` exits 2 with its error, either way writing nothing. Exit status 0 on success with one line on stderr naming what was written; 2 on any definition error, with nothing written and each objection on its own line as `api_gen: <definition>: <what is wrong>`. A definition that breaks the format's own rules draws every objection the loader finds, in the document order of the items they concern, except that a structural failure leaving nothing to parse (a file that is not TOML, a missing or malformed `[_general]`, an unknown top-level table) draws its own objection alone; one that satisfies them draws every objection every selected output has, and none from an output not selected, all in the same run, each once, as `api_gen: <definition>: <outputs>: <what is wrong>`, where `<outputs>` names every selected output raising that same objection, comma-joined in the order `header`, `wrapper`, `lua`, `stub`, `rust`, `rust_abi`, `rust_stub` (`header, wrapper, stub: struct.stats.int: 'int' is a C keyword`). A definition the format allows but the generator does not yet produce is refused the same way, the message saying `not implemented`. Every selected output is always written, and no other; staleness is the build's concern.

Dependencies: `python3 -m api_gen gendeps [--outputs=<list>] <definition>` prints make text to stdout for exactly one definition (one per project is the rule): `GENERATED :=` listing the selected outputs, `--outputs` as generation reads it, as `$(GEN)/...` paths with `$(BASE)` for the exercise directory, and one grouped-target rule (`$(GENERATED) &: definition`, GNU make 4.3 or later) making them by running the generation mode with `--generated $(GEN) --project $(BASE)` and the same selection as `--outputs`. The including makefile defines `GEN`, `BASE` and `API_GEN`. It reads the definition's `_general._name`, which names the outputs, and the output paths come from the same code the generation mode writes to, so a build file never spells them. A definition the loader refuses draws its objections as generation reports them, exit status 2, with nothing on stdout.

## Not generated

The wrapped API's header. It is the wrapped API's own, in whatever shape that API takes, and is never generated; the pins are the bridge. In this repository it is an exercise's driver UAPI header. The API's implementation is hand-written too: the stub is a starting point handed over once, and the generator never touches the implementation. A Rust implementation is hand-written in its crate root, `lib.rs`, behind the regenerated relay.
